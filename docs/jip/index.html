Curve host calls for proof verification

Five host calls give JAM services native-speed elliptic-curve arithmetic — the operations Ethereum ships as precompiles. Measured on a live net: proof verification 3 to 16× cheaper, and Aztec's own transaction proofs go from unverifiable to practical.

What a JIP is

A JAM Improvement Proposal: the process for amending the JAM protocol, kept by the Polkadot Fellowship at polkadot-fellows/JIPs — JAM's analogue of Ethereum's EIPs. A proposal gets its number when it is submitted; ours is a final draft, held back until the measurements in this repository are complete.

The problem

Verifying a zero-knowledge proof is mostly elliptic-curve arithmetic. JAM's VM has no cryptographic host calls, so that arithmetic runs as ordinary metered code — and pays for it. One verification of the proof Aztec uses for epochs costs 181M gas; a JAM core's budget per work-package is 5,000M. Aztec's per-transaction client proof is worse: 11.4B gas, more than two full packages, so no package can verify even one.

The proposal: add five host calls to the Gray Paper

Multi-scalar multiplication (MSM) and the pairing check, on the two curves deployed proof systems actually use, plus the MSM on BN254's cycle partner. Inputs use Ethereum's precompile encodings; prices come from end-to-end benchmarks on a reference machine.

CallNameServesPrice at a working size

103bls12_381_g1_msmEthereum's KZG blobs, BLS signatures66.1M at 128 points
104bls12_381_pairing_checkthe same5.3M at 2 pairs
105grumpkin_g1_msmAztec's client proofs (their inner-product argument ends on Grumpkin)1.93B at 215 points

Primitives, not verifiers: Barretenberg changed its proof format at every major release, but the curves never changed. An MSM and a pairing check outlive any one proof system.

Measured

Gas is the protocol's: identical on every conforming client. Measured on lasair, our JAM client, which implements the calls behind an activation flag; the same service blobs fall back to in-VM code on nets without them, losing at most 0.34M gas to the probe.

The last row is the one that changes what JAM can do. Aztec's per-transaction proof ends in one 215-point Grumpkin MSM; as in-VM code that single operation exceeds a package's whole budget. With the JIP we ran Aztec's own verifier, unchanged, as a JAM service on a live six-validator net: two different real Aztec transactions verified and finalized, and a tampered copy rejected.

A full package verifies 95 epoch-sized UltraHonk proofs instead of 27. Settling an Aztec epoch — its proof, blob openings and signatures — falls from about 813M gas to about 498M.

Status

  • Final draft, after two internal reviews: the full text, with the specification, pricing rule and test vectors. Its number is assigned at submission.
  • Implemented and running end to end: lasair implements all five calls, and Aztec's released stack settles on a six-validator lasair testnet with them. Every measurement above has its script in the repository.
  • Safe to adopt incrementally: services detect the calls at run time and fall back to in-VM code, so one blob serves nets with and without them.
