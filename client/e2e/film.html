What you are about to see is real

Aztec's proving stack, running live on a JAM chain. Simplified, not simulated.

Running in this recording

  • Noir 1.0.0-rc.5: a private-transfer circuit in Aztec's model. Notes, nullifiers, a depth-40 note tree, an indexed nullifier tree.
  • Barretenberg (bb.js 5.0.0): an UltraHonk proof, made in the sender's browser in about a second.
  • JAM: PolkaJam v0.8.0, six validators, GRANDPA finality. Refine verifies each proof on the PVM (147M gas); accumulate writes the trees.
  • JAM: lasair, our own client, six validators, GRANDPA finality, with the proposed curve host calls. Refine verifies each proof in 49M gas, 147M without them; accumulate writes the trees.
  • Sealed notes (X25519, AES-256-GCM), found by the receiver's own key. Keys never leave the browser.

Not in this recording

  • Not JAM as specified today. The curve host calls are our proposal; only lasair implements them, and the same service runs without them on PolkaJam.
  • Not the Aztec network. No Aztec kernel circuits, PXE, sequencer or Aztec.nr contracts. The circuit is ours, written to Aztec's shapes.
  • Not real money. A dev chain: a faucet, an unsigned public ledger, and Alice's and Bob's keys are public.
  • Not Aztec's note tagging (wallets try every note), and no folding (one proof per work package).

Separately, in the same repository, not shown here: Aztec's own client proofs checked in refine by Barretenberg's own verifier and finalized on lasair, and Aztec v6's unchanged node and PXE settling on JAM, so far with test-mode proofs.
